# 2026-07-28

## 报警规则页：资源路径来源与「设备不一致」根因
- 报警配置页 `AlarmRuleConfigView` 的向导式 ComboBox `ResourcePaths` 来自 DB `resource_nodes` 表（链路：`AlarmRuleConfigViewModel.LoadResourceTree` → `ResourceTreeService.Current` → `ResourceTreeRepository.LoadAllAsync`，仅取 `IsEnabled` 且 `Tag/Device` 节点）。
- 该表与「实际设备」（`AcquisitionHost.GetDevices()`，即设备模板/OPC UA/Modbus 驱动）**没有同步桥**：`ResourceTreeRepository.UpsertAsync/DeleteAsync` 定义了却从未被调用。
- 对比 `DeviceDetailViewModel.InitializeTreeFromAcquisitionHost`（line 83）在 resource_nodes 为空时回退到 AcquisitionHost 设备树——报警页**没有这个回退**，所以二者显示不一致。
- StackPanel 中的 `CustomTargetResourcePath/CustomResourcePath/CustomTagId` 是纯手动文本，不来自任何数据源，保存时直接写入 `AlarmDefinition`，不做校验。
- 修复方向：① 让报警页像 DeviceDetail 那样在 resource_nodes 为空时回退到 AcquisitionHost；② 或在设备发现后把 AcquisitionHost 树写入 resource_nodes（调用 UpsertAsync）以保持单一事实源。

## 方案2实施：ResourceTreeSynchronizer + 触发点接入
- 新建 `ResourceTreeSynchronizer.cs`（Core/ResourceTree）：AcquisitionHost → resource_nodes 表同步器
- App.xaml.cs 注册为单例；设备加载后 + 配置热重载时调用同步
- AlarmRuleConfigViewModel 订阅 ConfigurationReloadedEvent

## 报警不显示/不弹出致命bug修复
- **根因**：RegisterTestAlarmRules 硬编码 S7 TagId（tag-*），实际运行 Modbus（mb-*），RuleEngine 永远匹配不上
- **修复**：重写为 `RegisterDynamicAlarmRules`，按 TagName 模板 + AcquisitionHost 动态生成
- 同步修复 RegisterTrendTags 也改为动态查找模拟量 Tag
